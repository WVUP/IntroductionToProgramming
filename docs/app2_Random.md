# Appendix II: Random

A random number is a numerical value selected by chance, where each possible number has an equal probability of being chosen.  In computer science, random numbers are essential for tasks requiring unpredictability or statistical fairness, such as simulations, cryptography, and game mechanics.  For a sequence to be truly random, it cannot be possible to predict future values based on past values.  

One approach to this is to use the value of π, which is an infinite number and follows no defined pattern.  It is possible to calculate the value of any one digit of π.  By calculating one of these digits and using the numbers after that digit, it is possible to have an algorithm that will return random numbers.

Because computers calculate everything via an algorithm, it is not possible to have a computer generate a truly random number by itself.  To get a truly random number, it is possible to use a natural, external source, such as radioactive decay of an element or atmospheric noise, as an influence. However, these external sources are often not readily available on every computer.  What computers typically do instead is generate and use ***pseudorandom numbers***. 

Pseudorandom numbers are generated by algorithms called ***pseudorandom number generators*** (PRNGs).  While their sequences appear random, these algorithms are actually determined by an initial value called a ***seed*** value. If the seed is known, the sequence can be reproduced because these numbers are generated internally using an algorithm such as the one described based on π.  In the algorithm based on π, the seed number would be the digit of π to start calculating the random number.

A best practice to make the numbers different each time the application runs is to seed the random number generator with the current system time in milliseconds.  Since the application never runs twice at the exact same time, the PRNG will generate different numbers every time the application runs.  The Random class’ default constructor uses this approach.  If instead the same literal number is always used, the starting point in the value of π would always be the same, and the numbers generated would always be the same.  


# Declaration and Initialization
We need to first import the Random class in order to generate pseudorandom numbers within our application. This statement will need to be added at the top of the class outside of the class definition.

```java
 import java.util.Random;
 
 public class SystemManagement
 {
	...
 }
```

Similar to the Scanner class, this will allow you to call public methods declared in the Random class without having to explicitly call it each time you use it. We’ll have examples of both explicit and implicit calls in the following code segments.

Next, like any other class we want to use, we need to declare a variable of the Random class.

```java
 private Random rngA; //implicit call
 private java.util.Random rngB; //explicit call
```

For initialization, we set each variable to a new instance of the Random class. 

```java
 rngA  = new Random(); //implicit call
 rngB = new java.util.Random(); //explicit call
```

# Usage
The Random class has methods to generate values for various numerical data types. This also includes booleans because true and false can be referenced as either 1 or 0. For this section we will focus on *nextInt()*, with and without an upper bound, and *nextBoolean()*. Other methods and their functionality are defined in the [Random class documentation](https://docs.oracle.com/en/java/javase/22/docs/api/java.base/java/util/Random.html). We will also use the *rngA* variable declared earlier for the remainder of this section’s code examples.


## nextInt()
The *nextInt()* method generates and returns a random value that is available for the int data type. This means that it will use a value between -2,147,483,648 and 2,147,483,647. In the example below, we will generate 4 random numbers and print them.

```java
 for (int i = 0; i < 4; i++)
 {
	System.out.println( rngA.nextInt() ); 		
 }
```

*nextInt()* is an overloaded method in the Random class. It can accept an int which is then used to set an upper bound, or a maximum value, that can be generated. When this upper bound is provided, the range of values that can be used is from 0 (inclusive) to the upper bound (exclusive). For example, if I ran the same code, this time providing an upper bound of 10, the possible values that can be returned are 0 up to, but not including, 10.

```java
 for (int i = 0; i < 4; i++)
 {
	System.out.println( rngA.nextInt(10) ); 		
 }
```

<figure><figcaption>Console Output:</figcaption><pre>
5
8
0
1
</pre></figure>

Using the overloaded *nextInt()* method is great when you want to either provide a small value, such as the outcome after rolling a die. It’s also useful when you have a limited number of options to select from, like printing a greeting from an array or ArrayList for an NPC.

```java
 String[4] responses = {"Hello!", "Hi", "What do you want?", "..."}
 
 for (int i = 0; i < 4; i++)
 {
	System.out.println( responses[rngA.nextInt(4)] ); 
	//For the example output, assume the number generated is 1		
 }
```

</pre></figure>


## nextBoolean()
If you are wanting a randomized true or false value, *nextBoolean()* is the method to use.

```java
 for (int i = 0; i < 4; i++)
 {
	System.out.println( rngA.nextBoolean() ); 		
 }
```

<figure><figcaption>Console Output:</figcaption><pre>
false
true
true
false
</pre></figure>

*nextBoolean()* is also useful if you are wanting to simulate coin flips.

```java
 System.out.println("Let’s see if you are a winner…");
 
 //For the example output, assume the value generated is true
 if (rngA.nextBoolean() == true)
 { 
	System.out.println("You win the grand prize!!!");         	
 } 
 else
 {
	System.out.println("Sorry, try again next time.");         	
 }
```

# Summary
The Random class can make your application’s functionality unpredictable in the sense that the inputs and outputs generated don’t follow an easily determined pattern. However, remember that nothing in computer science is truly random. We as programmers tell the computer what algorithms to use. There is a pattern to the madness, we just make it difficult to see.
